# Minimind 系列笔记 03：训练全流程

> 源码：[jingyaogong/minimind](https://github.com/jingyaogong/minimind)（`trainer/` 目录，11 个训练脚本约 3000 行）。

MiniMind 的训练管线是一条完整的大模型后训练流水线缩影：

```text
Pretrain（学语言与知识）
  → Full SFT（学会对话格式，融入 mid-training 数据）
      → LoRA（低成本垂域适配）
      → 蒸馏（白盒 KL 对齐教师分布）
      → DPO（离线偏好对齐，off-policy）
      → PPO（在线 RL，Actor+Critic 双网络）
      → GRPO / CISPO（在线 RL，组内相对优势，单网络）
      → Agentic RL（多轮工具调用 + 延迟奖励）
```

本文先讲所有训练脚本共享的工程骨架（值得单拎出来学），再逐个拆解训练阶段的算法。

## 一、所有训练脚本共享的骨架

把 `train_pretrain.py` 抄一遍，几乎就是其他所有脚本的模板：

### 1.1 学习率调度

```python
def get_lr(current_step, total_steps, lr):
    return lr * (0.1 + 0.45 * (1 + math.cos(math.pi * current_step / total_steps)))
```

余弦退火（cosine decay）的手写版：训练开始 `lr × 1.0`（0.1 + 0.45×2），结束时 `lr × 0.1`（0.1 + 0.45×0）。**从不衰减到 0**——末端保留 10% 的学习率继续微调，这是与"归零版"余弦的实用差异（末端小步长继续收敛，但不至于完全停止学习）。每个 step 手动写回 `optimizer.param_groups`，不用 `torch.optim.lr_scheduler`（PPO/GRPO 例外，用了 `CosineAnnealingLR`）。

### 1.2 混合精度训练（AMP）

```python
dtype = torch.bfloat16 if args.dtype == "bfloat16" else torch.float16
autocast_ctx = nullcontext() if device_type == "cpu" else torch.cuda.amp.autocast(dtype=dtype)
scaler = torch.cuda.amp.GradScaler(enabled=(args.dtype == 'float16'))
...
with autocast_ctx:
    res = model(input_ids, labels=labels)
    loss = res.loss + res.aux_loss
    loss = loss / args.accumulation_steps
scaler.scale(loss).backward()
if step % args.accumulation_steps == 0:
    scaler.unscale_(optimizer)
    torch.nn.utils.clip_grad_norm_(model.parameters(), args.grad_clip)
    scaler.step(optimizer)
    scaler.update()
    optimizer.zero_grad(set_to_none=True)
```

默认 bfloat16（不是 fp16），这条选型值得展开：

- **fp16**：动态范围小（指数 5 位），前向易上溢/下溢，必须配 GradScaler——把 loss 先放大 N 倍，反传梯度同倍放大，optimizer.step 前再缩回来检查 inf/nan。所以 fp16 路径上 `scaler.scale→unscale_→step→update` 一套都不能少。
- **bf16**：指数位与 fp32 相同（8 位），动态范围大，不需要 GradScaler（`enabled=(dtype=='float16')` 关掉了它），损失部分精度但换来完全免调参。现代 GPU（A100/3090 Ampere 之后）都支持，已是训练默认。

**哪些计算不该进低精度**（01 篇已见到，这里集中归纳）：norm 的统计量（`.float()` 进出）、softmax（`.float()` 进出）、loss 累加。模式统一为"低精度算矩阵乘，fp32 算 reduction"。

**梯度裁剪必须在 `unscale_` 之后**——scale 状态下的梯度全部被放大了 100 倍量级，直接裁剪等于没裁（永远达不到 1.0 阈值之外的尺度）。`clip_grad_norm_(1.0)`。

`zero_grad(set_to_none=True)`：把梯度置 None 而不是 0，省一次 memset 且跳过后续的梯度更新判断，小优化。

### 1.3 梯度累积

```python
loss = loss / args.accumulation_steps    # 先除
scaler.scale(loss).backward()             # 每步都反传（梯度自然累加）
if step % args.accumulation_steps == 0:   # 每 N 步才 step 一次
    scaler.unscale_(optimizer); clip; step; update; zero_grad()
```

显存不够大 batch 时的标准解法：micro-batch 跑 N 次，梯度在 `.grad` 里自动累加（backward 不会清零），loss 预先除以 N 保证等效于大 batch 的平均损失，每 N 步才做一次 optimizer.step。默认 `accumulation_steps=8`，等效 batch = 32×8 = 256。

`train_epoch` 结尾的尾巴逻辑（`last_step % accumulation_steps != 0` 时补一次 step）处理"最后一个不满 N 步的窗口"——否则这批梯度会白白丢掉。

### 1.4 DDP 与随机种子

```python
local_rank = init_distributed_mode()          # 检测 RANK 环境变量，有则 init_process_group
if dist.is_initialized(): args.device = f"cuda:{local_rank}"
setup_seed(args.seed + (dist.get_rank() if dist.is_initialized() else 0))
...
if dist.is_initialized():
    model = DistributedDataParallel(model, device_ids=[local_rank])
for epoch in range(start_epoch, args.epochs):
    train_sampler and train_sampler.set_epoch(epoch)
```

DDP（DistributedDataParallel）是数据并行：每张卡一份完整模型，各吃各的数据，反向时梯度 all-reduce 求平均。三个实践点：

1. **种子按 rank 偏移**（`seed + rank`）：否则所有卡初始化和数据顺序完全相同，数据并行退化成单卡×N 浪费。每 epoch 再偏移（`seed + epoch`）保证轮间 shuffle 不同。
2. **`set_epoch` 必须调**：`DistributedSampler` 靠它改变各 epoch 的分片方式，不调的话每个 epoch 所有卡吃到相同的数据排列。
3. **保存权重只存 rank 0**（`is_main_process()`），且从 `model.module`（剥掉 DDP 壳）再剥 `_orig_mod`（剥掉 torch.compile 壳）拿原始模型。

03 篇 GRPO/PPO 里还有两个 DDP 的深坑注释（"反向传播必须经过 DDP 包装后的模块，直接调 .module 会跳过 prepare_for_backward，梯度不会 all-reduce，各卡静默发散"）——DDP 的 hook 挂在包装层的 forward 上，绕过包装层调用参数，all-reduce 时序就错了，而且**不报错、只是默默训废**，属于最阴险的一类 bug。

### 1.5 断点续训

```python
# lm_checkpoint 的双文件设计：
ckp_path   = f'{save_dir}/{weight}_{hidden_size}.pth'         # 纯权重（推理用）
resume_path = f'..._resume.pth'                                # 完整训练状态
resume_data = {
    'model': ..., 'optimizer': optimizer.state_dict(),
    'epoch': epoch, 'step': step,
    'world_size': ..., 'wandb_id': ...,
    # kwargs 里还可以塞 scaler / scheduler / critic 等任意组件
}
```

恢复 optimizer 状态是续训的关键：AdamW 的动量 $\beta_1$、二阶矩 $\beta_2$、当前 t 都在 state_dict 里，只恢复 model 不恢复 optimizer，等于重启了自适应学习率的记忆，loss 会跳变。两处细节：

- **world_size 转换**：续训时 GPU 数变了（8 卡→1 卡），step 坐标要按比例换算（`step * saved_ws // current_ws`）才能对上数据进度；
- **原子写入**（`.tmp` 写完 `os.replace`）：训练中途 kill 不会留下半个损坏的 checkpoint。

权重保存统一转 fp16 存盘（`v.half().cpu()`）——训练精度 bf16/fp32，发布权重 fp16，一份权重两套精度需求分开满足。

## 二、阶段一：Pretrain

数据与目标见 [02 篇](./02-Tokenizer与数据.md)。训练侧没有任何算法花活，就是骨架 + 最朴素的超参：

| 超参 | 值 |
|---|---|
| epochs / batch_size / accum | 2 / 32 / 8（等效 256） |
| learning_rate | 5e-4 |
| max_seq_len | 340 |
| loss | `res.loss + res.aux_loss`（MoE 时） |

预训练 lr 5e-4 是所有阶段里最大的——模型从随机初始化开始，参数需要大幅移动；后面 SFT 降到 1e-5（50 倍），保护预训练学到的能力。

## 三、阶段二：Full SFT

脚本与 pretrain 几乎逐行相同，差异全在数据侧（SFTDataset + loss mask）。超参对照：

| | Pretrain | Full SFT |
|---|---|---|
| lr | 5e-4 | **1e-5** |
| batch × accum | 32×8 | 16×1 |
| max_seq_len | 340 | 768 |
| from_weight | none | pretrain |

lr 降 50 倍的原因：预训练权重已经"很好"了，SFT 只是在流形上做局部微调，大 lr 会把预训练的能力灾难性遗忘掉。`from_weight` 链条（pretrain → full_sft → dpo/grpo/...）就是大模型训练的 stage 化管理——每个阶段都站在前一阶段的权重上。

## 四、阶段三：LoRA

### 4.1 实现：monkey-patch 旁路

```python
class LoRA(nn.Module):
    def __init__(self, in_features, out_features, rank):
        self.A = nn.Linear(in_features, rank, bias=False)     # 降维
        self.B = nn.Linear(rank, out_features, bias=False)    # 升维
        self.A.weight.data.normal_(0, 0.02)   # A 高斯初始化
        self.B.weight.data.zero_()            # B 零初始化

def apply_lora(model, rank=16):
    for name, module in model.named_modules():
        if isinstance(module, nn.Linear) and module.in_features == module.out_features:
            lora = LoRA(module.in_features, module.out_features, rank=rank)
            setattr(module, "lora", lora)
            original_forward = module.forward
            def forward_with_lora(x, layer1=original_forward, layer2=lora):
                return layer1(x) + layer2(x)
            module.forward = forward_with_lora     # 替换 forward
```

LoRA 假设：微调时的权重更新 $\Delta W$ 是**低秩**的，可以分解为 $\Delta W = BA$（$B: d \times r$，$A: r \times d$，$r \ll d$）。前向变成 $Wx + BAx$，只训 A、B，冻结原权重。

三处实现细节：

1. **B 零初始化**：训练开始时 $BA = 0$，模型行为与原模型完全一致——从"已训练好的状态"出发做增量，而不是从一个随机扰动的状态出发。
2. **默认路径闭包陷阱的规避**：`def forward_with_lora(x, layer1=..., layer2=...)` 用默认参数把变量**当场定值**。若写成闭包引用外层变量，循环里所有层会共享最后一次的值（Python 闭包晚绑定的经典坑）。
3. **只 patch 方阵 Linear**（`in_features == out_features`）：q/k/v/o/gate/up/down 都是 768→768 或 2432→2432 的方阵，lm_head（768→6400）不 patch——输出投影动了会直接改写词表分布，容易破坏通用能力。

训练时只把 lora 参数给 optimizer：`optim.AdamW(lora_params, lr=1e-4)`。lr 是 1e-4，比 full SFT 大 10 倍——可训练参数少了 99% 以上，需要更大的步长才能学动。LoRA 参数占比实测：约 1.2M / 64M ≈ 1.9%。

### 4.2 保存与合并

```python
def save_lora(model, path):        # 只存 lora 权重（几 MB）
def merge_lora(model, lora_path, save_path):
    ...
    state_dict[f'{name}.weight'] += (module.lora.B.weight.data @ module.lora.A.weight.data).cpu().half()
```

`merge_lora` 把 $BA$ 加回原权重，推理零开销（没有额外分支）。注意 merge 在 fp16 下做矩阵乘有精度损失（BA 的乘积先 half 再加），教学代码可接受，生产实现一般 fp32 merge。

## 五、阶段四：知识蒸馏

```python
def distillation_loss(student_logits, teacher_logits, temperature=1.0, reduction='batchmean'):
    teacher_probs = F.softmax(teacher_logits / temperature, dim=-1).detach()
    student_log_probs = F.log_softmax(student_logits / temperature, dim=-1)
    kl = F.kl_div(student_log_probs, teacher_probs, reduction=reduction)
    return (temperature ** 2) * kl
```

蒸馏原理（Hinton 2015）：教师 softmax 的输出是"暗知识"（dark knowledge）——"猫 0.9、狗 0.08、汽车 0.02"里狗和猫的相似度信息比 one-hot 标签丰富得多。**温度 T** 软化分布：T 越大，小概率的次优 token 被放大，暗知识越显形；T² 是梯度尺度补偿因子（logits/T 的梯度量级会缩 1/T²，乘回来保持 loss 量级与 CE 可比）。

总损失是混合的：`loss = alpha * ce_loss + (1-alpha) * distill_loss`（默认 alpha=0.5，T=1.5）：

$$\mathcal{L} = \alpha \cdot \mathcal{L}_{CE} + (1-\alpha) \cdot T^2 \mathrm{KL}(p_{teacher}^T \,\|\, p_{student}^T)$$

CE 锚住 ground truth（防纯蒸馏漂移），KL 传递教师的分布偏好。两个实现要点：

- **只在 loss mask 的 token 上算 KL**：`student_logits.view(-1, v)[loss_mask_flat == 1]` 先过滤——prompt 位置的教师分布没有学习价值；
- **词表裁剪**：`teacher_logits[..., :vocab_size_student]`——MoE 教师（198M）蒸馏 dense 学生（64M）时若词表不同，取前 N 对齐。README 的演示配置正是 moe→dense。

与 SFT 的关系：SFT 教"正确答案是什么"（one-hot 蒸馏，黑盒），白盒蒸馏教"每个候选 token 的相对倾向"。README 区分了黑盒蒸馏（拿强模型输出做 SFT——R1 蒸馏就是这个路线）和白盒蒸馏，这个脚本是后者的参考实现。

## 六、阶段五：DPO

### 6.1 原理

RLHF 的原始管线（PPO 式）需要：训奖励模型 → 用奖励模型在线指导策略。DPO（Direct Preference Optimization）的推导证明：KL 约束的奖励最大化目标存在闭式解 $r(x,y) = \beta \log \frac{\pi(y|x)}{\pi_{ref}(y|x)}$，代回偏好模型后**可以跳过显式的奖励模型**，直接从偏好对优化策略：

$$\mathcal{L}_{DPO} = -\mathbb{E}\left[\log \sigma\left(\beta \left[\log \frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \log \frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\right]\right)\right]$$

直觉读法：拉大"策略模型认为 chosen 好于 rejected 的程度"与"参考模型认为的差距"。参考模型 $\pi_{ref}$ 充当锚——防止策略无约束地把 rejected 概率压到零的同时把 chosen 也搞崩（那不是变好，是分布漂移）。

### 6.2 实现

```python
def dpo_loss(ref_log_probs, policy_log_probs, mask, beta):
    ref_log_probs = (ref_log_probs * mask).sum(dim=1)      # 整段回答的 logprob 求和
    policy_log_probs = (policy_log_probs * mask).sum(dim=1)
    # batch 前半是 chosen，后半是 rejected
    chosen_ref = ref_log_probs[:batch_size // 2]
    reject_ref = ref_log_probs[batch_size // 2:]
    ...
    pi_logratios = chosen_policy - reject_policy          # log π(y_w)/π(y_l)
    ref_logratios = chosen_ref - reject_ref               # log πref(y_w)/πref(y_l)
    logits = pi_logratios - ref_logratios
    loss = -F.logsigmoid(beta * logits)
    return loss.mean()
```

实现与公式逐项对应：

- `logits_to_log_probs` 用 `gather` 抠出每个真实 token 的 logprob，mask 后 sum 得到整段回答的对数概率 $\log \pi(y|x)$（序列级似然，不是逐 token 平均）；
- chosen / rejected 在 batch 维拼成一个大 batch 过模型（2 次前向 → 1 次），减少 kernel launch；
- $\beta$（默认 0.15）控制"贴多紧参考模型"：越大越保守。lr 是全场最小（4e-8，脚本注释：建议 ≤5e-8 避免遗忘）——DPO 的梯度集中在压低 rejected 上，步子大了通用能力崩得极快。

模型侧：`ref_model` 与 policy 完全同构，`requires_grad_(False)` + `eval()`，等于存了两份 SFT 权重。

### 6.3 定位

README 的总结很到位：DPO 是 **off-policy**（静态偏好数据集、可多轮 epoch）、免奖励模型、实现简单；但它不做在线探索，更多用于"偏好/安全"对齐，对"能不能做对题"的能力提升有限。

## 七、阶段六：PPO / GRPO / CISPO

### 7.1 统一视角

README 给了一个所有 Policy Optimization 算法的统一目标：

$$\mathcal{J}_{PO} = \mathbb{E}_{q \sim P(Q),\, o \sim \pi_\theta}\left[\underbrace{\Phi(r_t, A_t)}_{\text{策略项}} - \underbrace{h(\text{KL}_t)}_{\text{正则项}}\right]$$

三组件 = 策略项（概率比 $r_t$ 和优势 $A_t$ 怎么组合）× 优势项（$A_t$ 怎么估）× 正则项（怎么约束别跑偏）。DPO / PPO / GRPO / CISPO 全部是这个框架的实例化：

| 算法 | 策略项 | 优势项 | 正则 | 模型数 |
|---|---|---|---|---|
| DPO | $\log r_w - \log r_l$ | 无（偏好对隐式） | 隐含在 β | 1（前向 2） |
| PPO | $\min(r A, \text{clip}(r, 1\pm\varepsilon) A)$ | Critic + GAE | $\beta\cdot\text{KL}$ | 2（+Critic） |
| GRPO | 同 PPO | 组内归一化 $\frac{R-\mu}{\sigma}$ | $\beta \cdot \text{KL}_t$ | 1 |
| CISPO | $\min(r, \varepsilon_{high}) \cdot A \cdot \log\pi$ | 同 GRPO | $\beta \cdot \text{KL}_t$ | 1 |

### 7.2 共享的基建：Rollout 引擎

PPO/GRPO/AgentRL 共享一个抽象（`rollout_engine.py`），这是理解现代 RL 训练系统的关键：

```python
class RolloutEngine(ABC):
    @abstractmethod
    def rollout(self, prompt_ids, attention_mask, num_generations, max_new_tokens, temperature=0.8) -> RolloutResult: ...
    @abstractmethod
    def update_policy(self, model): ...

class TorchRolloutEngine(RolloutEngine):     # 直接调模型 generate
class SGLangRolloutEngine(RolloutEngine):    # HTTP 调远程推理服务
```

`RolloutResult` 携带五件套：`output_ids`（完整序列）、`completion_ids`（生成部分）、`per_token_logps`（每个生成 token 的 logprob——RL 需要）、`completions`（文本）、`completion_mask`。**训推分离**：训练侧只管优化 policy，rollout 侧负责高吞吐采样；每批更新完 `update_policy` 把新权重同步过去（SGLang 版走 `/update_weights_from_disk` HTTP 接口）。当前实现是同步模式（采完一批更一批），还没有异步 rollout buffer——但 openrlhf/verl 的雏形已经在了。

奖励函数（三份脚本共用逻辑）：

```python
rewards[i] += 0.5 if 20 <= len(response) <= 800 else -0.5        # 长度合规
if '</think>' in response:
    rewards[i] += 1.0 if 20 <= len(thinking) <= 300 else -0.5    # 思考长度
    rewards[i] += 0.25 if response.count('</think>') == 1 else -0.25  # 格式闭合
rewards[i] -= rep_penalty(answer)                                 # 重复惩罚
score = reward_model.get_score(messages, answer)                  # InternLM2-1.8B-Reward 打分
```

规则奖励管格式（长度、思考标签闭合、重复度），奖励模型管内容质量。为什么用**模型打分而不是规则二元奖励**？README 讲透了小模型 RL 的根本困难——**奖励稀疏**：0.1B 模型做数学题几乎全错，二元 0/1 奖励全零 → 组内优势 $A = r - b \approx 0$ → 梯度信号消失。连续分数奖励（-2.5~+3.0）保证"再差也有区分度"，让小模型在能力边界内仍有梯度可学。

### 7.3 PPO：双网络 + GAE

PPO 涉及四个模型，是小模型上能跑的最复杂实现：

- **Actor**：策略模型，要训练；
- **Critic**：价值估计网络（`CriticModel` = MiniMind 主干 + `value_head: 768→1`），要训练；
- **Ref**：冻结的 SFT 权重，算 KL 正则；
- **Reward Model**：冻结的 InternLM2-1.8B，给整段回答打分。

核心循环里最值得学的是 **GAE（Generalized Advantage Estimation）**：

```python
token_rewards = torch.zeros_like(old_resp_logp)
token_rewards[arange(B), last_idx] += rewards   # 序列级奖励放到最后一个 token

lastgaelam = 0; advs_rev = []
for t in reversed(range(gen_len)):              # 时间反序递推
    nv = old_resp_values[:, t+1] if t < gen_len-1 else 0.0
    delta = token_rewards[:, t] + gamma * nv - old_resp_values[:, t]   # TD 误差
    lastgaelam = delta + gamma * lam * lastgaelam
    advs_rev.append(lastgaelam)
advantages = torch.stack(advs_rev[::-1], dim=1)
returns = advantages + old_resp_values
```

奖励是稀疏的（整段回答一个分，放在最后 token 上），GAE 通过 TD 误差 $\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$ 的指数加权递推，把这个终局奖励**沿序列反传分布**到每个 token，$\lambda$ 控制偏差（纯 TD，低方差高偏差）与方差（纯蒙特卡洛，高方差低偏差）的权衡。

PPO 的 clip 目标：

```python
log_ratio = mb_resp_logp - old_resp_logp
ratio = torch.exp(log_ratio)
policy_loss = max(-adv*ratio, -adv*clamp(ratio, 1-ε, 1+ε))    # 保守更新
value_loss = 0.5 * max((V-returns)², (clamp(V, old±0.2)-returns)²)  # value 也 clip
```

`old_resp_logp` 是 rollout 时的 logprob（重要性采样的"旧策略"）；ratio 偏离 1 太多（新策略相对采样策略漂移过大）的部分被 clip 掉，防止单步更新过激。整批 rollout 还可以复用 `ppo_update_iters=2` 轮（PPO 唯一允许的数据复用——importance sampling 修正了分布偏移）。

还有三个工程防御，都是实战血泪：

1. **早停 KL**：`approx_kl > 0.25` 时本轮停止更新（loss 乘 0 保住 forward-backward 闭环，DDP 不挂）；
2. **all_reduce 同步 approx_kl**：各卡独立判断早停会导致某卡 break 其它卡继续 → DDP 死锁；
3. **debug_log_ratio**：验证"首轮第一个 minibatch 的 ratio≈1"——不≈1 说明 rollout 与训练的实现有数值错位（dropout 未关、token 对不上等），这是 RL 实现最常见的静默 bug。

README 的实测结论：PPO reward 提升缓慢——Critic 要先收敛才能给 Actor 提供靠谱优势估计，两者相互依赖；显存也是单网络方法的 1.5-2 倍。

### 7.4 GRPO：去掉 Critic

GRPO 的核心一步：**同一个问题采 N 个回答，用组内平均分当 baseline**：

```python
rollout_result = rollout_engine.rollout(prompt_ids, ..., num_generations=6, ...)  # 每题 6 采样
rewards = calculate_rewards(...)                     # (B * 6)

grouped_rewards = rewards.view(-1, num_generations)  # (B, 6) 分组
mean_r = grouped_rewards.mean(dim=1).repeat_interleave(num_generations)
std_r  = grouped_rewards.std(dim=1).repeat_interleave(num_generations)
advantages = (rewards - mean_r) / (std_r + 1e-4)     # 组内标准化 = 优势
```

$$A_{i,j} = \frac{R_{i,j} - \mu_i}{\sigma_i + \epsilon}$$

同一题的 6 个回答互为参照：高于组均值的被鼓励、低于的被抑制。**Critic 网络整个不需要了**——组均值就是 value 的蒙特卡洛估计。loss 是 PPO 式的 clip 目标 + **token 级** KL（对 ref 逐 token 算 $\exp(\Delta) - \Delta - 1$，这是 k3 估计量，恒正、低方差，比直接 $\Delta$ 平滑）：

```python
kl_div = ref_per_token_logps - per_token_logps
per_token_kl = torch.exp(kl_div) - kl_div - 1
ratio = torch.exp(per_token_logps - old_per_token_logps)
clipped = torch.clamp(ratio, 1-ε, 1+ε)
per_token_loss = -(min(ratio*adv, clipped*adv) - β*per_token_kl)
policy_loss = ((per_token_loss * completion_mask).sum(1) / completion_mask.sum(1)).mean()
```

`completion_mask` 是 EOS 之前的有效区域（EOS 之后的 padding token 不该参与 loss）：

```python
is_eos = (completion_ids == eos_token_id) & completion_pad_mask
eos_idx[is_eos.any(dim=1)] = is_eos.int().argmax(dim=1)[is_eos.any(dim=1)]   # 第一个 EOS
completion_mask = (arange(R) <= eos_idx.unsqueeze(1)) & completion_pad_mask
```

实测曲线：GRPO 的 reward 稳定上升且收敛上限高于 PPO（单网络、无 Critic 依赖）。GRPO 的软肋是**退化组**——如果某题 N 个回答得分几乎一样，$\sigma \to 0$（分母有 1e-4 兜底但分子同样趋零），整组学习信号≈0。小模型能力弱，退化组出现频率更高，所以训练必须限定在能力边界内的任务。

### 7.5 CISPO：改一行 loss

CISPO（Clipped Importance Sampling PO）观察到一个别扭的问题：PPO/GRPO 的 clip 把 ratio 截断成常数后，**梯度流也被硬切断了**——被 clip 的 token 在这次更新里完全失聪。CISPO 把策略项改写成"截断权重 × log 概率"：

$$\mathcal{L}_{CISPO} = -\mathbb{E}\left[\min(r_t, \varepsilon_{high}) \cdot A_t \cdot \log \pi_\theta(a_t|s) - \beta \cdot \text{KL}_t\right]$$

ratio 即使被截断，也只作为**系数**，梯度走 $\log \pi_\theta$ 路径继续回传。实现上就是 GRPO 脚本里的一个 if：

```python
if args.loss_type == "cispo":
    clamped_ratio = torch.clamp(ratio, max=args.epsilon_high).detach()   # 上界截断，detach 掉 clip 分支
    per_token_loss = -(clamped_ratio * advantages.unsqueeze(1) * per_token_logps - args.beta * per_token_kl)
else:
    ...  # GRPO 原版
```

注意 `.detach()` 加在 clamp 后的 ratio 上——权重是常数，梯度只流过 `per_token_logps`。`epsilon_high=5.0` 只设上界（ratio 很大时截断防爆炸，ratio 很小时保留梯度让它继续学）。MiniMind 没有为 CISPO 单独写脚本，直接作为 GRPO 的 loss 变体——这也印证了"XXPO 都是同一框架的实例化"。

### 7.6 Agentic RL：多轮工具调用

`train_agent.py` 把 RL 从"单轮问答"扩展到"多轮交互"。数据 `(x, T, gt)`：问题 + 工具集 + ground truth。优化对象不再是单个回答，而是**整条轨迹**：

$$\tau = (a_1, o_1, a_2, o_2, \dots, a_T), \quad a_t \sim \pi_\theta(\cdot \mid s_t, \mathcal{T})$$

rollout 过程（`rollout_single`）：

```text
模型生成 → 含 <tool_call>？→ 是：解析 JSON → 执行工具（mock 环境）→
结果包进 <tool_response> 拼回上下文 → 继续 rollout（最多 max_turns 轮）
→ 无 tool_call 且给出最终回答 → 结束
```

奖励对整条轨迹联合打分：

$$R(\tau) = R_{\text{answer}} + R_{\text{tool}} + R_{\text{format}} + R_{\text{rm}} - R_{\text{unfinished}}$$

答案命中 gt（Agentic RL 终于用上了规则可验证奖励——工具调用场景下数学题有唯一答案，不存在奖励稀疏问题）、工具调用合法性、格式闭合、未完成惩罚、RM 分数。梯度回传在整个轨迹结束后才发生（延迟奖励），并且要把多轮拼接的每段 logprob 都收集起来（`response_ids.extend(new_ids)` 逐轮累积）。

README 对这套实现的定位："模板组织、工具执行、多轮 rollout、延迟奖励、训推分离"的最小串联——工业级 Agent 训练框架（verl/slime）的骨架已具备，只是每处都取了最简形态。

两条值得记录的实验观察（都来自 README 实测曲线）：

1. **PPO vs GRPO**：PPO reward 缓慢爬升（双网络互锁），GRPO 稳定上升且上限更高（单网络）；
2. **RL 的代价**：RL 权重的 reward score 更高，但通用能力和知识面会退化（reward hacking / capability trade-off）——RL 优化的是奖励函数的代理，不是真实能力。发布的 transformers 版模型一般从 full_sft 而不是 RL 权重转换，就是这个原因。
