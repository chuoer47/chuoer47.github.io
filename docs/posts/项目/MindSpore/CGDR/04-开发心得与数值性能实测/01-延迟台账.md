# 01 · 延迟台账（310P3 实测 + 本报告派生量）

> 数据全部搬自 `PLAN.md` 与 `docs/`（未跑任何新实验）。标 **本报告计算** 的是我从这些数字算出来的派生量，附算式。

## 结论先行

1. **Cube 化（!1135）带来 1.35x~6.32x 的加速，峰值 6.32x 出现在 `1×16×128×128×128`（7.273ms → 1.151ms）**；6 shape 加速比几何平均 **4.29x**、算术平均 4.77x、区间 [1.35x, 6.32x]（`PLAN.md §Step A+B 结论 L97-104` + 本报告计算）。
2. **Cube 化的收益在 a9c66ddb（分支第一个 commit，8/13）一天内全部兑现**：同一 shape `1×16×128×128×128` 上 a9c66ddb=1.151ms、终态 d0906c3e=1.132ms（09-14 同日对照）、向量化基线 00e39ab5=7.273ms → a9c66ddb 已拿到总收益的 **99.69%**，后续 5 个 commit 只贡献 0.019ms（`PLAN.md §中间 commit 实测矩阵 L132-137`、`PLAN.md L81` + 本报告计算，算式见 §5）。5 个大 shape 的兑现率 98.17%~99.95%。
3. **「泛化重构零性能损失（六 shape 差 <1.5%）」这条文档结论在其自身表格上不完全成立**：按 `PLAN.md L132-137` 逐 shape 重算，a9c66ddb→725cf45d 有 **3 个 shape 超过 1.5%**（`1×8×64×64×64` −7.78%、`1×1×128×128×256` −7.80%、`1×16×128×128×128` −1.65%）。但亚毫秒 shape 的**绝对差只有 66~73µs**，与"同一构建跨天自漂移"同量级（§8）→ **方向性结论（重构不掉性能）成立，文档给的 1.5% 阈值与自身数据不符**。4 个 ≥1.13ms 的 shape 最大偏差 1.65%，3 个 ≥4.3ms 的 shape 全部 ≤1.10%。
4. **两个修复（!1158+!1174）零性能开销成立**：048d0427 vs d0906c3e 同日（09-08）逐 shape 差值中，**唯一变慢的是 `2×8×512` +0.41% 和 `1×16×1024` +0.13%**，其余为变快；表面上的 −8.43%（t2048）经跨天对照判定为 d0906c3e 当日离群值（§7）。
5. **端到端延迟与流水线数据自洽**：msprof 单 kernel ~955µs vs 同 shape 端到端 1.151ms = **83.0%**，8 核并行没有串行化（`docs/PR-1135-d0906c3e/11-流水线剖析msprof实战.md §1.3` + 本报告计算）。
6. RGDR（!1140）**从未产出任何延迟数据**——它的 perf 用例被 deselect（`PLAN.md L14`），因此本报告不纳入跨算子性能比较。

## 3. 峰值位置与加速比分布

- **峰值 6.32x 在 S2 = 1×16×128×128×128**（`PLAN.md L100`，本报告精确化到 6.3189）。这个 shape 同时也是 msprof 流水线的代表 shape（`docs/PR-1135-d0906c3e/11-流水线剖析msprof实战.md §1.1` 选它作被测 shape，注释写"Cube 化收益最大的那个"）。
- **区间**：[1.35x, 6.32x]；**6 shape 几何平均 = 4.2940x**（本报告计算）：
  `exp((ln1.3534+ln6.3189+ln4.3791+ln5.7848+ln5.6358+ln5.1341)/6) = exp(8.7437/6) = 4.294`。
  等价乘积式：`(1.3534×6.3189×4.3791×5.7848×5.6358×5.1341)^(1/6) = 6268.2^(1/6) = 4.294`。
- **算术平均 = 4.7677x**（28.6062÷6），比几何平均高 0.47 倍——被 S1 这个 1.35x 的离群小 shape 拉开，所以对外报告应优先用几何平均或"区间 + 峰值"。
- **剔除 S1（唯一没吃到 Cube 收益的 shape）后的 5 shape 几何平均 = 5.4094x**（本报告计算）→ "典型收益 ≈5.4x" 是比"6.3x"更不失真的说法。
- 048d0427 口径的几何平均 **4.4280x**（本报告计算，同一算式换分母），比 d0906c3e 口径高 0.13 倍，全部来自 S6 的跨天离群（§7）。

**S1 为什么只有 1.35x**：docs 未解释。可核对的事实是 S1 是 6 个 shape 里唯一 Dk=Dv=64（≤`kSmallCubeDk=64`，`src/d0906c3e/op_host/chunk_gated_delta_rule_tiling.cpp:43`）、且 T=64 只有 1 个 chunk 的 shape——工作量最接近 kernel launch + 装载的固定成本地板。此归因为**本报告推断，非文档结论**。

## 5. 「Cube 收益一天内全部兑现」的算术依据

算式（同一 shape S2，三个数来自不同表）：

```
总收益        = 00e39ab5 − d0906c3e(09-14) = 7.273 − 1.132 = 6.141 ms
a9c66ddb 已兑现 = 00e39ab5 − a9c66ddb       = 7.273 − 1.151 = 6.122 ms
兑现率        = 6.122 / 6.141 = 99.69%        残留 = 0.019 ms = 0.31%
加速比        = a9c66ddb 6.3189x  vs  终态 6.4249x   （本报告计算）
```

- 三个输入分别来自：`PLAN.md L82`（7.273）、`PLAN.md L133`（a9c66ddb 1.151 / d0906c3e 1.132）。
- **更强的一条**：09-08 当日 d0906c3e 的 S2 实测就是 **1.151ms**（`PLAN.md L100`），与 09-14 的 a9c66ddb **同一个数** → 在这个 shape 上后续 5 个 commit 的净性能贡献为 **0.000ms**（本报告计算）。

## 8. 测量噪声地板（同一构建、不同日期）

d0906c3e 在 09-08 与 09-14 各测一次（`PLAN.md L97-104` vs `L129-137` 末列，本报告计算）：

| shape | 09-08 ms | 09-14 ms | Δ% | Δms |
|---|---|---|---|---|
| S1 | 0.928 | 0.869 | −6.36% | −0.059 |
| S2 | 1.151 | 1.132 | −1.65% | −0.019 |
| S3 | 0.831 | 0.794 | −4.45% | −0.037 |
| S4 | 4.355 | 4.340 | −0.34% | −0.015 |
| S5 | 8.746 | 8.737 | −0.10% | −0.009 |
| S6 | 18.954 | 17.4 | **−8.20%** | −1.554 |

**这就是本台账的解释上限**：同一个二进制的相对偏差可达 6.4%（S1）/ 8.2%（S6），绝对偏差在 ≤1ms 的 shape 上是 37~59µs、在 S6 上是 1.55ms。所以：

- 任何 <1% 的单 shape 差异（S4/S5 级别）不能当作性能变化解读；
- 亚毫秒 shape 的 <8% 差异不能当作回归/收益解读；
- 只有"跨 shape 一致的方向 + 大 shape 的量级"（例如 Cube 化的 5~6 倍）才是可下结论的信号。
