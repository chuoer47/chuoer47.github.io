# 技术架构

整体是一个标准的 Next.js 15 App Router 全栈应用:页面和交互组件跑在客户端,所有涉及模型和第三方 API 的调用收敛在服务端 API routes,密钥永不进入浏览器。

## 分层结构

```
src/
├── app/            # 路由、页面、API routes
│   ├── api/
│   │   ├── chat/route.ts              # 星体聊天
│   │   ├── explore/random/route.ts    # 随机抽星
│   │   ├── explore/chat/route.ts      # 记忆库自由提问
│   │   ├── official-knowledge/[id]/   # 官方天文数据卡片
│   │   └── search/route.ts            # 图鉴语义检索
│   ├── chat/  explore/  memory/  library/
│   ├── classroom/  wish/  wish-wall/
│   └── knowledge/[id]/  admin/  ...
├── components/     # 儿童交互组件(bottom-nav、chat-experience 等 19 个)
├── data/           # 星体、知识卡片、课堂内容(静态数据层)
├── lib/            # 聊天、检索、语音、天文 API 适配
└── types/          # 共享类型定义
```

职责划分:

- `data/` 是**静态知识层**:星体目录(`celestial-bodies.ts`,345 行)、知识卡片(`knowledge-cards.ts`,295 行)、探索种子目录(`exploration-catalog.ts`)、课堂模块(`classroom-modules.ts`)。这些是人工审核过的"兜底真相",模型回答必须优先依据它们。
- `lib/` 是**服务端能力层**:聊天管线(`chat.ts`,437 行)、语义检索(`retrieval.ts`)、NASA 适配(`official-astronomy.ts`)、语音(`speech.ts`)、模型配置(`model-config.ts`)。全部标了 `import "server-only"`,保证不会被客户端组件意外引入。
- `app/api/` 是**薄路由层**,做参数校验后直接调 `lib/`,不写业务逻辑。

## 模型配置:三级降级

`src/lib/model-config.ts` 实现了一个简单的 provider 选择链:

```ts
export function getRuntimeModelConfig(): RuntimeModelConfig {
  if (process.env.KAFU_LLM_API_KEY) {
    return { provider: "kafu", chatModel: process.env.KAFU_CHAT_MODEL || "qwen3-max", ... };
  }
  if (process.env.OPENAI_API_KEY || process.env.GPT_API_KEY) {
    return { provider: "openai", chatModel: process.env.OPENAI_MODEL || "gpt-4o-mini", ... };
  }
  return { provider: "local", chatModel: "local-fallback" };
}
```

优先用阿里云 DashScope(KAFU)的 `qwen3-max`,其次任何 OpenAI 兼容端点,**一个密钥都没有时应用照常运行**——聊天和随机探索退回本地兜底内容。这保证了演示现场没网、没密钥都不会白屏。由于用的是 Vercel AI SDK 的 `createOpenAI` 兼容层,切换 provider 只是换环境变量,代码零改动。

## 聊天管线:先分类,再生成

`src/lib/chat.ts` 的 `generateGroundedReply` 是整个 App 的核心。它不是简单把用户消息丢给模型,而是一条**先本地规则分类、再决定是否调用模型**的管线:

```
用户输入
  │
  ├─ 命中 dangerKeywords(自杀/伤害/爆炸/投毒/违法)
  │    → buildDangerReply:本地模板,拒绝并引导回星空
  ├─ 命中 privacyPattern(电话/学校/邮箱/手机号正则)
  │    → buildPrivacyReply:提醒不要透露个人信息
  ├─ 命中 refusalKeywords(作业/考试答案/黑客/武器/色情/算命…)
  │    → buildRefusalReply:"这已经飞出我的星轨了"
  ├─ 不是天文问题、也不是陪伴场景
  │    → buildBridgeReply:接住话头,引导回星空话题
  │
  └─ 是天文/陪伴问题
       ├─ 无模型密钥 → 本地知识卡片组装回复(local-fallback)
       └─ 有密钥 → generateText,带完整 system prompt + 知识上下文
```

这样设计的原因:**危险和隐私拦截必须在模型之前**。大模型的 prompt 约束是软的,关键词前置过滤是硬的——儿童产品里这一层不能省。

模型调用时的 prompt 组装也值得说。system prompt 是 11 条硬规则的清单(只能围绕天文、必须优先依据本地知识资料、资料不足要明说"不确定"、神话与科学事实必须区分、回复控制在 150-260 汉字、三段式结构……),user prompt 则由四块拼接:

```
本地知识资料:      buildKnowledgeContext(body.id)   ← 知识卡片
语义检索补充片段:  buildRetrievalContext(trimmed)   ← 跨天体检索
最近对话:          最近 6 条,每条截断到 300 字
用户这次的问题:    原文
```

这是最小可行的 RAG:知识卡片做 grounding,检索做跨天体关联("你也可以延伸看看:木星、土星"),模型只负责把事实翻译成孩子听得懂的话,而不是编造事实。对话历史会被 `sanitizeChatHistory` 清洗(校验结构、截断长度、只留最近 6 条),防止 prompt 注入式的超长输入。

生成失败(`catch`)时静默降级到本地 `buildGroundedReply`,用户无感知。

## 随机抽星:官方数据 + 人设生成

`/api/explore/random` 的流程:

1. `pickRandomExplorationSeed(excludedIds)` 从探索目录里随机挑一个天体种子(冥王星、木卫二、泰坦……每条有 `childHint` 这类儿童视角提示)
2. `getOfficialAstronomyForSeed(seed)` 调 NASA API:NASA Image and Video Library 拿真实图片、APOD 拿今日天文图片、Exoplanet Archive 拿系外行星参数,统一整理成带 `source` 的 facts(每个数据点都标注来源)
3. `generateExplorationPersonality(seed, official)` 让大模型为这个天体生成儿童可读的科普摘要和性格设定,返回 JSON(有 `extractJson` 容错解析和 `normalizeGenerated` 字段校验,模型输出不合法就退回模板人设)

NASA 调用有 4.5 秒超时(`AbortController`),失败返回 `status: "fallback"` 并使用本地数据——**官方数据不可用时,宁可用审核过的兜底内容,也不编造具体参数**,这是科普产品的科学边界。

## 语义检索:不依赖向量库的 cosine

`src/lib/retrieval.ts` 实现了一个轻量的中文语义检索:对 query 和文档做 Unicode script 分词(连续汉字段 + 汉字二元切分 + 英文单词),建词频向量,算 cosine 相似度,阈值 0.06 过滤。检索对象是四类文档:星体、知识卡片、文化条目、课堂模块。

没有引入向量数据库和 embedding 服务,是因为语料总量只有一千多行、四百多个文档——在内存里建倒排的代价远小于维护一个向量库,且部署到 Serverless 函数时无冷启动依赖。`/api/search` 暴露这个能力给图鉴页,聊天管线也复用它做跨天体检索补充。

## 语音:浏览器原生能力

`src/lib/speech.ts` 基于 `window.speechSynthesis`,没有引入任何 TTS 服务:按偏好列表挑选中文女声(xiaoxiao/tingting 等),`speakGently` 控制语速音调做到"温柔朗读",`stopSpeech` 支持随时打断。语音输入同样用浏览器原生的 Speech Recognition。零成本、零延迟、离线可用,对儿童产品是性价比极高的选择。

## 数据存储:localStorage

愿望、抽星记忆、课堂进度全部存 `localStorage`,不建账户、不传服务器。数据模型上做了失效防御(读取时逐字段校验类型),浏览器清数据后内容丢失是已知且可接受的取舍。
